Title: Web SPA: players, quiz, round summary, stats, leaderboard

## Summary

Builds the React SPA against the `shared/` contract: Who's playing? grid with add and delete, the quiz (large photo, seven emotion buttons with keys 1-7, instant feedback with the contrast photo on a miss, progress bar, resume after reload), round summary, stats page (per-emotion bars, per-angle accuracy, 7x7 confusion heatmap, recent rounds) and leaderboard. Every response is parsed with the shared schemas, and every data view has loading, error and loaded states. Closes #4.

`VITE_MOCK_API=true npm run dev -w web` serves `/api` from in-memory MSW handlers (`web/src/mocks/mockApi.ts`). It is an explicit opt-in, the nav shows a "Mock API" badge while on, and it is documented in CLAUDE.md's Running section. The same handlers back the Vitest suites.

## Notes for reviewer

No changes to `shared/`. Outside `web/`: `eslint.config.js` gets an override so the generated `web/public/mockServiceWorker.js` (from `npx msw init`) is not linted, `.prettierignore` skips it, `CLAUDE.md` documents mock mode, and `package-lock.json` picks up `msw`.

Deviation from `docs/process/testing.md` ("stub fetch at the boundary"): the web tests use MSW, as the issue asks; `testing.md` still says to stub `fetch` and could be updated. The test setup wraps `fetch` to resolve relative URLs against the jsdom origin, since Node's fetch rejects them.

The per-emotion chart uses recharts, which renders nothing in jsdom, so an accessible table carries the same numbers and the tests assert on that. The quiz layout (image fits the viewport without scrolling on tablet and phone) was not checked in a real browser: the embedded browser pane could not register the MSW service worker, so mock mode was verified only up to the dev server serving the worker script.

Contract observations, none blocking: the answer response has no `playerId`, so stats and leaderboard are invalidated by key prefix rather than for the one player; the API's 409 duplicate-name message is shown verbatim, so its wording is the server's; the unranked list shows "needs N more answers" from `totalAnswered` (not `windowAnswered`), assuming `minAnswers` counts all answers.
